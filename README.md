# Beacon 🔆

**Find the city that feels like you — then the work and home waiting there.**

**Live:** [beacon-ejo.pages.dev](https://beacon-ejo.pages.dev) · ![CI](https://github.com/iqmouse/beacon/actions/workflows/ci.yml/badge.svg) · 56 tests · zero dependencies · MIT

Beacon asks twenty-seven unhurried questions and matches you against **173
researched cities** on six continents — with a transparent formula instead of
a model. No AI at runtime, no API keys in the client, no accounts required,
nothing sold. Same answers, same result, every time, and the app will explain
exactly why ("how the light works", on the results page).

![Skylines and home portraits, all generated by the app's own code](docs/og.png)

## Why it's built this way

Recommendation products usually hide their reasoning. Beacon's founding
constraint was the opposite: **every number a user sees must be traceable to
either a cited source or an openly-admitted judgment call, through arithmetic
they could check by hand.** That constraint shaped everything:

- The matching engine is a pure function (`src/scoring.js`) — no randomness,
  no network, no state. It runs identically in the browser and under
  `node --test`, which is why it has real tests instead of screenshots.
- The jobs, pay bands, and home listings are *labeled samples* generated from
  each city's actual industries and researched cost data — never fake
  listings dressed up as real ones. Live listings (via a server-side proxy)
  ride on top only where real coverage exists, tagged as such.
- Even the art is deterministic: every city's skyline and every home's
  portrait is drawn by seeded canvas code, so Lisbon always looks like
  *that* Lisbon.

## The matching engine

Each answer builds a profile across fourteen dimensions. Nine are a weighted
symmetric fit (`1 − |you − city| / 10`): pace, nature, culture, social,
climate, food, transit, openness, scale. The other five refuse to be
symmetric, because real preferences aren't:

| Dimension | Shape | Rule |
|---|---|---|
| **Language** | capability | A shared language is full credit; English-friendliness is partial; your willingness to learn carries the rest. "Dealbreaker" pins same-language cities to the top. |
| **Cost** | one-way, monotonic | A cheaper city **never** scores worse on cost. A big budget only flattens the over-budget cliff — it can't turn expense into a virtue. Over-budget cities are forgiven *only* where they measurably deliver the quality you named (working transit, culture, nature). |
| **Safety** | floor + escape valve | Your midnight-walk answer sets the floor; your tradeoff answer (culture / cheapness / nature) defines what forgives a rougher city — individually, per user. |
| **Diversity** | one-sided care | Wanting the world on one street favors Toronto over Kyoto. Not caring penalizes no one. |
| **Visas** | rules, not vibes | Passport blocs (EU freedom of movement, UK–Ireland CTA, Mercosur residence, trans-Tasman) plus per-country entry tiers. Results separate "live & work in N" from "visit M visa-free". |

The weighted mean is raised to a power to spread the field; ties break
alphabetically, so ranking is fully deterministic. These invariants aren't
aspirations — each is pinned by a named test (e.g. *"big budget must not
score Zurich above Prague on cost"*, a real bug report that became a
regression test).

## Architecture

```
index.html          dev entry (full HTML5 document + module script)
styles/beacon.css   all styling (dusk/dawn themes, reduced-motion aware)
src/
  util.js           $, store, clamp — plus esc()/safeHttpUrl(), the XSS boundary
  data.js           173 cities: dims, languages, cost, industries, neighborhoods
  questions.js      the 27 questions (order is load-bearing; wording is not)
  visas.js          passport groups, bloc rules, per-country entry tiers   [pure]
  scoring.js        the matching engine                                    [pure]
  skyline.js        seeded generative skylines + home portraits
  audio.js          generative score (D-minor pentatonic) + reactive UI sound
  homes.js          seeded home listings + real-portal links               [pure]
  jobs.js           honest job availability from each city's economy       [pure]
  main.js           views, rendering, lantern, profiles, wiring
functions/api/      optional Cloudflare Pages Functions backend (see below)
test/               56 cases on node's built-in runner — still zero deps
build.js            dependency-free bundler → dist/ (app, 173 static city
                    pages, sitemap, robots, 404) + build/artifact.html
tools/make-icons.py stdlib-only PNG writer for the app icons
```

The build is a line-level transform over the repo's own conventions, not a
compiler. `dist/index.html` is one self-contained file that runs anywhere a
browser runs.

```bash
python3 -m http.server 4173   # develop (plain ES modules, no toolchain)
npm test                      # 56 tests, node --test, zero dependencies
npm run build                 # dist/ (single file + 173 city pages + SEO files)
npm run deploy                # build + push to Cloudflare Pages
```

## The optional backend

`functions/api/[[path]].js` adds accounts and live job listings on the same
free Cloudflare Pages project, with a D1 (SQLite) database. The client probes
`/api/me` once, off the critical path — everywhere the API doesn't exist (a
saved file, the claude.ai artifact) Beacon behaves exactly as before.

- **Auth**: email + password, PBKDF2-SHA256 (150k iterations, WebCrypto),
  30-day sessions behind an `HttpOnly; Secure; SameSite=Lax` cookie scoped to
  `/api`. Signing in **merges** your device's saves with the account's
  (union by id) — it never overwrites them.
- **Live jobs**: a proxy to Adzuna with keys held in Pages secrets, responses
  normalized, escaped, and edge-cached for six hours.

One-time setup: create a D1 database, put its id in `wrangler.toml`, apply
`schema.sql`, and set `ADZUNA_APP_ID` / `ADZUNA_APP_KEY` as Pages secrets.

## Security model & known limits

This section exists because a pre-launch review (three parallel reviewers
over the backend milestone) found four real vulnerabilities — all fixed, each
with a regression test:

1. **XSS via third-party job data** reaching `innerHTML` (amplified by the
   shared edge cache) → every dynamic string now passes through `esc()`, and
   hrefs through an http(s)-only allowlist.
2. **Login CSRF** via `text/plain` form smuggling (SameSite=Lax doesn't stop
   a cross-site response from *setting* a cookie) → all non-GET API routes
   require same-origin + `application/json`.
3. **Stored XSS via synced profile data** → same `esc()` gate.
4. **HTML metacharacters in emails** → the validator refuses `<>"'&`.

Honest remaining limits, by choice and by scale: open signup with no email
verification or password reset (a reset needs an email provider, which breaks
the no-keys budget); no rate limiting beyond Cloudflare's; visa rules and
market data drift and deserve an annual review; sample pay is **illustrative
USD from a cost-of-living formula, not local wage data** — and is labeled as
such in the app.

## Things this project taught me

- **Asymmetry is the whole game in preference modeling.** The first cost
  model treated "willing to spend" as symmetric distance — which quietly
  ranked Zurich as a better *cost* match than Prague for big spenders. Users
  noticed. The fix (strict monotonicity with a quality-gated exception) is
  the most interesting twenty lines in the repo.
- **Honest sample data needs louder labels than you think.** "Generated by
  formula" in a footer wasn't enough; every card now says *sample*.
- **`String.replace` treats `$'` as a substitution pattern.** The bundler
  corrupted itself on code containing a literal `$'` until every replacement
  became a function. Cheap lesson, memorable scar.
- **A deterministic app can still feel alive** — generative skylines, a
  generative score, a glow that breathes: all seeds and formulas, no dice.
